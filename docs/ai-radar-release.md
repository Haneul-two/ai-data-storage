# AI Radar 재설계 반영 기록 — 2026-10-12

현재 사용자 요청: 전문가용 UI/UX, GPT 6.1 SOL 최대 추론으로 디자인 조사, 한국시간 신청 마감 제외, 수집 범위 확대, AI Radar 명칭.

## 구현과 독립 검증

- GPT 6.1 SOL(max)의 Devpost·Kaggle·Linear·Luma·Carbon 조사로 마감 중심 비교 목록과 상세 패널을 선정했다. 구현은 Claude, 코드·실제 화면 검증은 Codex가 맡았다. 기존 `design.md`와 `design-lab/radar/DESIGN.md`, 네 가지 시안 `design-lab/radar/options.html`에 근거가 있다.
- 상단 검색, 유형과 정렬, 두 열의 필터/비교 목록, 상세 드로어, 모바일 세로 행으로 재설계했다. 320~1440px에서 가로 넘침뿐 아니라 제목 폭도 확인했다.
- `assets/visibility.mjs`가 목록·건수·검색·달력·저장·임박·상세의 노출 기준을 통일한다. 확정 마감/종료는 제외하고 저장 ID와 원본은 보존한다. 날짜만 있는 오늘 마감은 오늘 끝까지, 미확정 미래 행사는 확인 필요로 남긴다.
- 10개 출처를 실제로 갱신했다. 새 출처는 콘테스트코리아·Dev-Event·AI EXPO KOREA다. Devpost 목록은 최대 5페이지, 콘테스트코리아는 AI 12 + 인공지능 3페이지, 위비티는 최대 6페이지다. robots·HTTPS·허용 호스트·요청 간격·본문 상한을 유지한다. 운영 LLM API 사용은 없다.
- 행사 디렉터리의 공통 출처 주소가 ID 충돌을 일으킨 것을 실수집에서 확인했다. 해당 출처만 행사 링크로 ID를 생성하도록 바꾸고 1회 조회한 응답으로 선택 갱신했다. 다른 9개 출처 항목과 확인 시각은 그대로 보존했다.
- 로컬 최종 데이터 165건 중 현재 노출은 118건(공모전 82·행사 22·해커톤 14), 마감·종료 47건은 제외된다. 이 수치는 이후 날짜와 운영 수집에 따라 변한다.
- 검사 근거: Python 228개, Node 118개, 실제 Edge UI 98개. 세부 증거는 `docs/evidence/radar-directory-fix.txt`, `radar-frontend-checks.txt`, `radar-live-collection.txt`와 최종 검증 결과다.

## 남은 보완과 제한

- 기존 미래 마감 항목이 목록에서 조기 마감으로 바뀌면, 상세를 다시 읽지 않고 명시적 마감 상태만 전파한다. 단순히 사라진 항목은 기존 stale 보존 정책을 유지한다. 마감 관찰은 기존 출처의 항목에만 적용하고 본문 확인 시각과 다른 필드는 보존한다. 전체 회귀 228개가 이 동작을 포함한다.
- 이 보완 중 Claude Sonnet과 Haiku가 모두 세션 한도에 도달했다(19:00 KST 재설정 안내). 한도 전에 Claude가 운영 코드를 작성했으며, 남은 실패는 이번에 새로 작성한 테스트 파일의 fixture 분류 코드 오타 두 곳이었다. 새 파일 작성은 Codex가 할 수 있는 사용자 규칙에 따라 오타를 고쳤고 전체 검사와 코드 독립 리뷰를 마쳤다. 기존 운영 소스의 편집은 계속 Claude가 담당했다.
- 실제 예약 시각에 발생한 cron 실행은 아직 검증하지 않았다. 운영 반영과 수동 수집 결과는 후속 `docs/evidence/radar-production.json`으로 기록한다.
- 개편 중 작성된 AGENTS/CLAUDE/verification의 로컬 대기 기록보다, 이 반영 기록과 실제 production 증거의 시점을 우선 확인한다. 기존 문서의 배포 이후 상태 동기화도 Claude 사용 한도 해소 후 남은 작업이다.

## 조사와 사고 기록

후보별 반려 이유와 데이터 한계는 `docs/evidence/radar-source-audit.md`에 있다. 조사 중 온오프믹스 목록을 robots 확인 완료 전에 1회 요청한 것은 규칙 위반이었다. 응답은 폐기했고 수집기에 사용하지 않았으며 추가 요청하지 않았다. 운영 Fetcher는 robots를 요청 전에 강제 확인한다.
